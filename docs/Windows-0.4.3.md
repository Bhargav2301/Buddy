The installed baseline remains **0.4.2 / dd87c798a5973277856261a3410b804073cd951b**. This report tracks the next local preview, not an installed or published release. Installation is withheld and publication is blocked. Five isolated specialist handoffs were reviewed and integrated. In Voice settings, **Start speaking complete sentences while Buddy prepares the rest** enables staging only for a bounded set of neutral text-only local voice prompts, such as "Explain rainbows." Saved memory, screen/image/web context, unsupported prompt forms and excluded history keep the existing whole-answer path. The lead must be a complete answer with its qualifications; later model calls may add optional detail. These checks are conservative routing, not a semantic safety proof. Teaching and action review remain separate.

[LocalVoiceOutput](../apps/windows/Buddy.Windows/LocalVoiceOutput.cs) holds one output endpoint and one cancellation owner across generation gaps. [SentencePlayback](../apps/windows/Buddy.Windows/SentencePlayback.cs) overlaps current playback with the next sentence's preparation, with no device fallback. Preflight refusal before emission can use the whole-answer path; generation/review failure after emission stops without replay or saving a partial answer as complete. Actual first-audio latency and physical device behavior remain unverified.

**General > Use compact pointer and activity** changes the companion presentation; disabling it restores the mascot. **Guide & Agent > Guidance ink lifetime** selects 5, 15 or 30 seconds while retaining earlier invalidation. **Brains > Save disconnected draft** stores only provider/model dropdown choices. It continues to display **Not connected - live activation unavailable** and does not activate a provider.

## Evidence

The final integrated build passed **1,092 application assertions**: 797 service/policy/mock checks and 295 native checks in owned fixtures. The native total includes 45 new parity checks. Release build finished with zero warnings and zero errors. The coordination checker separately passed 12 tests; these are development-workflow tests, not application checks. Logs are named `team43-final-*` in the local validation directory and tied to an unchanged build-input snapshot.

The real local `gemma3:4b` probe used only the canned question "Explain rainbows." over loopback, with no microphone recording or audio playback. Three attempts took the whole-answer fallback: the first two plans were malformed, and after a format-only prompt clarification the third lead still contained three sentences. The validator correctly emitted no staged sentences; the final answer completed and was stored. **Real-model staged generation and first-audio latency acceptance did not pass.** The option remains off by default; it must not be presented as a proven latency improvement with this model. Mock overlap tests establish pipeline behavior only. No validation gate was weakened.

Independent QA reproduced two baseline cancellation races: a pre-cancelled cached request could emit events, and Stop while waiting for the state-store gate could still save a response. The fixes check cancellation after reading the store and inside the update callback; all six independent root-source regression checks passed.

The team completed a controlled pause/resume checkpoint: intake refused while paused, all five actual worker HEADs and snapshots were reconciled, and intake resumed only afterward. Late output from an already accepted worker was refused without changing integration files. Package launch/provenance results belong to the separate package receipt; physical audio, third-party application and live-provider acceptance remain open.

The installed 0.4.2 evidence remains separate: 754 service/policy and owned native-fixture assertions, plus a separate 24-assertion local vision run containing two real local-model checks. See the [0.4.2 report](Windows-0.4.2.md) and [evidence ledger](development/EVIDENCE.md). Those results do not validate new source changes.
