# Buddy 0.3.7 local Guide repair

The reported repeated fallback was emitted after two rejected planner responses. Capture had reached planning, but the 0.3.6 validator required every section's control to exist in the current UIA snapshot. Later menus could invalidate the entire lesson. The Guide also rendered its fallback twice.

Lessons now survive unavailable future targets. Only exact, unique, enabled current controls receive ink, rechecked against the pinned source window. General guidance is labelled explicitly and remains navigable; reviewing or skipping is never proof of completion. The exact Notepad introduction has a local three-section lesson independent of model schema reliability. Typing “teach me…” now routes to Guide.

Draw an area is available directly from Guide as an explicit one-use selection, without changing the saved region shortcut preference. Repeated teaching requests return focus from Buddy to the pinned source before capture; they never steal focus from another app. UIA observation remains bounded to one worker/two seconds, 400 nodes and a 600 ms traversal budget; image capture still requires complete privacy inspection.

Mixed teach-and-perform requests prepare a teacher, action planner and imported-notes researcher as real bounded jobs. At most two read-only jobs overlap. Local model inference remains serialized; all GUI changes remain in the single reviewed action runner with individual approvals and Stop/cancel-all.

Prompts settings adds default-off local suggestions. One allowlisted focused AI-chat field's text-change events are debounced; known private/sensitive contexts and unsupported fields are skipped. Suggestions never save incidental text, use screenshots, copy/paste or submit. A nonactivating permission card stays at the original field, supports a voice yes/no reply through the existing voice shortcut, shows highlighted changes and requires Accept. Guarded replacement refuses changed text; Undo is available for 30 seconds. Third-party field compatibility still needs hands-on acceptance.

The supplied complete character uses pointer-directed tilt and movement, plus listening/speaking/thinking poses. Its baked-in face remains one layer: no duplicate eyes or mouth. Independent pupil/blink/mouth artwork animation is not implemented.

Native WPF implementation. Clicky reference re-inspected: https://github.com/AbhishekVulla/clicky-windows (MIT). No Clicky source or PyQt dependency was copied; the repository's existing attribution/licensing remains. Buddy's stronger pinned-window, privacy-completeness and independent pointer validation checks remain.

Local-model fixtures and owned native windows are not real Notepad/Amoeba or physical microphone/headphone acceptance. No security setting, account authorization, paid provider, cloud speech service, merge or push is included.
