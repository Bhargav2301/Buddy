# Existing features: reversible presentation and retained state

The requested product scope is the source-verified Clicky/Coucou union, plus **prompt refinement as the only additional feature**. The [upstream matrix](Upstream-union.md) defines that union by platform and evidence. Existing Buddy capabilities outside it remain recoverable. This inventory distinguishes the installed presentation toggle from proposed future destinations; it does not authorize deleting data, revoking pairings, enabling services or changing the installed profile.

Inventory basis: installed and verified Buddy **0.4.4 / 950095dc1f8d1ce86b0f17bf8919a3465344e369**. Optional island and reversible core-first presentation are implemented and covered by owned native checks; installation receipts record preserved schema-3 contents, 32 nonappearance preferences and the selected voice, with Night Mint applied. See [Windows-0.4.4](Windows-0.4.4.md). The [0.4.5 Buddy-draft refinement batch](Remaining-union-0.4.5.md) has integrated evidence and does not replace the installed application.

In General settings, **Show core controls first** defaults off. Turning it on hides settings entries Connectors, Internet, Skills, Channels and Devices, and Home entries Devices, Memories, Prompts and Agent task. Turning it off restores them; there is no separate **Advanced / existing features** page. Region controls remain available. **App notes** is a relabelled route to the existing combined Task Center, not a completed knowledge/jobs split. This is presentation only: background behavior, permissions, stored data and existing enablement do not change.

The preview advanced refinement controls apply to Buddy-owned drafts. Supporting resources and explicit budgets for the original field in another application remain a separate missing workflow; the quick inline path is retained to preserve focus, field identity and Undo. Moving a task into Buddy's composer does not establish completion of that external-field requirement.

The installed user report identifies Comet Guide failure and browser-field refinement that accepted the unchanged original. The old Guide message identifies a failed process-query boundary; its historical HWND and cause were not recorded. The separate 0.4.5 preview adds pinned window/process lifetime checks and actionable refocus/retry, truthful no-refinement handling and a bounded inline footer. Its Buddy-owned, UFO-inspired observe/checkpoint/single-launch/verify adapter handles exact supported app-open requests while preserving Agent/privacy settings, Stop and broader action approval. No upstream framework or general computer-use runtime was installed. Integrated validation and actual-browser acceptance remain separate. Reported speech recognition and Notepad success are retained; installed 0.4.4 is untouched.

## Reversible migration contract

The installed core-first toggle changes navigation only. Restore hidden entries by turning **Show core controls first** off in General settings. A dedicated **Advanced / existing features** route is a possible future convenience, not an installed capability. Do not silently change `AgentEnabled`, `AllowWebResearch`, microphone/capture permissions, paired devices, retention settings or background activity because a control moved. Any deliberate operational disablement needs its own visible state and explicit action; visibility is not an authorization switch.

Keep schema-3 collections (`Conversations`, `Devices`, `Memories`, `Prompts`, `Audit`, `Guides`, `Jobs`, `Knowledge`) intact, preserve unknown preference fields, and make new presentation preferences default safely when absent. Preserve the user's current voice choice rather than restoring an old audition preset. No file deletion or profile downgrade is part of this plan.

For future presentation changes, compare saved-state contents/preferences against a fresh snapshot, exercise core-first on/off, confirm Stop/cancellation and review controls remain reachable, and verify interrupted jobs do not replay. Toggling back must restore access without data restoration. Native navigation/cancellation and the fresh installed-profile preservation checks passed for 0.4.4; no 0.4.5 profile migration or acceptance is claimed. Existing recovery archives remain separate from source and must not overwrite newer user data.
