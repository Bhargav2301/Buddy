# Buddy: pinned upstream union and core scope

The target is the verified Clicky/Coucou feature union, with **prompt refinement as the only additional feature**. A feature present in one upstream platform is a candidate requirement, not proof that it exists on another platform or already works in Buddy. This report separates source inspection, implemented Buddy behavior, mock/owned-fixture evidence and actual runtime acceptance. No upstream runtime acceptance is claimed.

Current installed checkpoint: **0.4.4 / 950095dc1f8d1ce86b0f17bf8919a3465344e369**, verified with preserved settings and Night Mint. Its 1,563 service/native assertions and 26 real local-model checks are historical evidence for that checkpoint, not acceptance of new work. The [0.4.5 remaining-work matrix](Remaining-union-0.4.5.md) records the tested Buddy-draft refinement preview and the separate remaining union gaps. Current scoped tests and limits are recorded in [Windows-0.4.5](Windows-0.4.5.md); no 0.4.5 installation acceptance is claimed.

The installed user report identifies Comet Guide failure and browser-field refinement that accepted the unchanged original. The old Guide message identifies a failed process-query boundary; its historical HWND and cause were not recorded. The separate 0.4.5 preview adds pinned window/process lifetime checks and actionable refocus/retry, truthful no-refinement handling and a bounded inline footer. Its Buddy-owned, UFO-inspired observe/checkpoint/single-launch/verify adapter handles exact supported app-open requests while preserving Agent/privacy settings, Stop and broader action approval. No upstream framework or general computer-use runtime was installed. Integrated validation and actual-browser acceptance remain separate. Reported speech recognition and Notepad success are retained; installed 0.4.4 is untouched.

## Coherent core UI

The installed optional island provides Hidden/Compact/Expanded states and routes to typed chat, Voice, Guide, Refine, Select area, Stop, Home and settings. Hidden is the default. It displays one local activity summary; it does not embed the chat composer/provider picker or implement session cards. Local readiness is a cached observation, and providers remain disconnected. Future status cards need identity, timestamps and observed terminal state before they can be called monitors.

Use the original Buddy character. Preserve existing blink/gaze/mood behavior and reduced-motion support, then independently implement any missing poke, sleep and completion reactions with explicit states. Detachable/wardrobe behavior is a separate macOS-derived candidate, not a prerequisite for claiming this small Windows island preview complete. Imported Coucou character/name/icon/sound assets are excluded.

Keep selected-window/region capture and attachment review explicit. A pending attachment must show its source, bounded content/type and removal control before use. An app title or browser URL cannot be presented as an observed screenshot. UI convenience must not widen capture, retention, provider transmission or action grants. Unsupported local file attachment types remain refused until a safe implementation exists.

The core surface should not advertise legacy jobs, Android pairing, workflow preparation or planned connectors as the user's next task. Keep them accessible through the [reversible existing-feature plan](Existing-feature-migration.md), preserving data and current operational settings. Reorganizing a menu must not delete history or silently activate/deactivate a capability.

## Refinement adaptation: implemented core and in-progress UI

The inspected [technique catalog][f-techniques] exposes eight manually selected techniques: Zero-shot, Few-shot, Chain-of-thought, Tree-of-thoughts, Role/persona, Prompt chaining, ReAct and Meta/reflection. [Managed inference][f-managed] requests role-labelled proposals in one structured call; the [legacy OpenRouter flow][f-council] makes parallel calls followed by synthesis. Do not call simulated roles independent agents. [Context extraction][f-context] uses balanced head/tail excerpts and labels omitted turns; [extension consent/context][f-extension] distinguishes user-reviewed reference from assistant suggestions. These are source patterns, not proof that new Buddy behavior has passed.

Automatic technique selection and a verified destination-limit registry are not established upstream features. Buddy's [RefinementCore](../services/Buddy.Server/RefinementCore.cs) already implements deterministic automatic selection, manual overrides and prerequisite checks. [RefineStream](../services/Buddy.Server/Refinement.cs) calls that selector, context builder and budget logic in production. The installed [Buddy-draft window](../apps/windows/Buddy.Windows/RefineWindow.cs) exposes quick/guided/council and a technique picker, but supplies no support inputs or explicit budget and does not display the full result metadata. The [external inline window](../apps/windows/Buddy.Windows/InlinePromptWindow.cs) always requests quick/automatic refinement and keeps its strict focus contract.

Budgeting must name the limit and count unit. Upstream [input limits][f-limits] and managed output validation use JavaScript string length (UTF-16 code units), distinct from inference token estimates; the [extension request schema][f-extension] lacks a `maxCharacters` field. Buddy supports UTF-16 code units, Unicode scalars and UTF-8 bytes, retains required blocks/confirmed constraints, removes optional scaffolding first and returns a conflict rather than clipping required content. Its [context core](../services/Buddy.Server/RefinementContext.cs) distinguishes user-confirmed data from suggestions and keeps imported text untrusted. These service/core boundaries have 0.4.4 evidence, including 185 focused synthetic assertions; no installed desktop controls for these inputs follow from that count. No verified destination registry or URL retrieval provider is connected.

The 0.4.5 preview exposes prerequisites, brief selection rationale, explicit unit/limit, reviewed pasted or bounded local TXT/MD resources, omissions/conflicts/warnings, and invalidate old acceptance whenever options/resources change. It must not request private chain-of-thought, execute listed tools, follow resource links, import files into long-term knowledge or widen the source-field quick path beyond the separately documented no-op/footer repairs. Scoped implementation and integrated results are now recorded in [Windows-0.4.5](Windows-0.4.5.md); see the [remaining-work matrix](Remaining-union-0.4.5.md).

Advanced technique inputs, supporting resources and destination budgets in the **original external application field remain missing**. Completing Buddy-draft controls does not close that target workflow. Future work must preserve the original field's identity, explicit review, focus safeguards and exact Undo; unsupported editors continue to refuse safely.
