# Buddy and Clicky Windows: evidence and implementation status

Compared against Clicky Windows **04f221f91d4750363d7032bcfd355b7dbc5c0e06**. Buddy **0.4.4 / 950095dc1f8d1ce86b0f17bf8919a3465344e369** is installed and verified, including the earlier local recognition, speech-feedback and 0.4.3 source changes. The [0.4.4 report](Windows-0.4.4.md) records accepted reliability/core UI and Night Mint evidence. The separate [0.4.5 refinement UI batch](Remaining-union-0.4.5.md) has integrated evidence in [Windows-0.4.5](Windows-0.4.5.md) and is not installed. Publication remains blocked. Source parity does not establish acceptance in every real application.

**Exactly same** below means the narrowly stated functional contract, never identical code, artwork, visual appearance or performance. **Similar** includes partial support and deliberate privacy differences. **Missing** means the stated capability is absent from the usable product. A fixture pass does not turn an unsupported browser or disconnected provider into a working integration.

Installed 0.4.4 evidence is 1,563 application assertions (1,145 service/policy/mock and 418 native owned-fixture checks), plus 26 real local-model checks. Earlier 0.4.3 had 1,092 application assertions and 12 separate coordination tests; those totals are historical, not additional 0.4.5 passes. Installation/profile preservation is recorded in the private release receipt. **Mock-tested** describes only an actually reported mock result; **live-unverified** remains separate from implementation status.

The pre-0.4.4 installed-service audit reproduced an Agent/Guide routing-plan error, failure to honor an explicit one-sentence request, and an accepted refinement that invented requirements. The corresponding 0.4.4 repairs passed bounded synthetic, owned-native and canned real-model checks; history below distinguishes those repairs from still-open physical/third-party acceptance. The [upstream union](Upstream-union.md) separately maps Coucou platforms/licenses and the requested refinement extra; [legacy feature presentation](Existing-feature-migration.md) is reversible.

The installed user report identifies Comet Guide failure and browser-field refinement that accepted the unchanged original. The old Guide message identifies a failed process-query boundary; its historical HWND and cause were not recorded. The separate 0.4.5 preview adds pinned window/process lifetime checks and actionable refocus/retry, truthful no-refinement handling and a bounded inline footer. Its Buddy-owned, UFO-inspired observe/checkpoint/single-launch/verify adapter handles exact supported app-open requests while preserving Agent/privacy settings, Stop and broader action approval. No upstream framework or general computer-use runtime was installed. Integrated validation and actual-browser acceptance remain separate. Reported speech recognition and Notepad success are retained; installed 0.4.4 is untouched.

## Sequencing and acceptance

The 0.4.2 core batch implements same-source lesson follow-ups, explicitly selected-window images, multiple independently verified drawings, completed-answer sentence prefetch, and opt-in encrypted teaching Q&A. These are functional changes with source and fixture evidence, not a claim of identical Clicky visuals or universal app compatibility. The original character artwork and action-approval boundaries are retained.

The 0.4.3 source adds optional staged sentence model calls, compact pointer/activity, bounded ink lifetime and disconnected provider/realtime text components with a local setup draft. Staging uses narrow neutral prompt forms and conservative history checks, not a general semantic safety classifier. Integrated mock/native results and the failed real-model staging acceptance probe are detailed in the [preview report](Windows-0.4.3.md). These results establish neither physical acceptance nor live-provider integration.

The installed 0.4.4 batch repairs the measured routing/schema, explicit tighter-response-limit and refinement-fidelity failures, and adds the optional core island/reversible navigation and Night Mint. It passes 1,563 service/native assertions and 26 real local-model checks within the [reported scope](Windows-0.4.4.md). Its refinement selector/context/budget service core is wired; the Buddy-draft manual technique picker already exists. The [0.4.5 batch](Remaining-union-0.4.5.md) is exposing support inputs, explicit budgets, reviewed resources and useful result metadata, with stale acceptance invalidation. The scoped preview has integrated evidence; it is not installed.

Remaining gaps include reliable staged first-audio behavior on the tested model, token-time first-audio streaming, an explicit long-answer override, Guide imported-pack retrieval, convenient per-app resources, universal custom-editor replacement, live cloud models and realtime/cloud speech. Local partial Whisper and version-aware app documents are additional enhancements, not features established in Clicky's corresponding local source. Multi-monitor capture and silent automatic retention are intentionally excluded. Piper voice choices/pacing do not guarantee cloud voice naturalness, emotion or accent handling.

Advanced resource, technique-input and explicit-budget controls in the **original external application field** also remain missing. The 0.4.5 Buddy-draft composer work does not close that workflow gap; source-field quick refinement and its focus/review/Undo safeguards remain unchanged.

Activating a cloud provider would first require a reviewed live connection and production routing, selecting a provider/model, explicit approval for the exact text/images/audio shared and any cost budget, secure credential entry and live acceptance. Saving a disconnected draft does none of these. Existing consumer subscriptions or ChatGPT connectors grant Buddy no API access. Realtime or cloud speech needs a separate explicit audio-sharing decision; neither is enabled here. No further approval is needed for the already authorized local core work.

The preview contains only the bounded native app-opening adapter described above. Validation uses owned WPF fixtures plus an authorized actual-Comet read-only observation; it does not drive browser input, install UFO or establish general computer use. The smallest remaining browser check is to focus the real Grok composer, invoke Refine source field, and verify review/Accept/Undo changes only that field without submitting. Unsupported capability refusal is a valid safe result, not a compatibility pass.
