# Buddy 0.3.9: resident companion and original-field refinement

Use the configured chat/voice shortcuts or click the companion to talk. Right-click it for Type, Guide, area selection and optional tools. Home provides history/settings; **Hide Home - keep Buddy running** and its window close button preserve the configured companion and service. **Exit Buddy (stops companion)** really exits. Snooze, hidden-companion preference and actual borderless fullscreen still affect visibility.

To improve a prompt in a supported AI composer, focus that original field before summoning Buddy, then choose **Refine source field**. The direct shortcut is Ctrl+Alt+R. Buddy keeps a short-lived metadata-only reference to the original HWND and UIA field before its own window takes focus. Explicit refinement reads that exact field and shows a highlighted review over it, or alongside a small field. Accept changes only that field; Undo restores it for 30 seconds. Neither sends the prompt. Changed field identity, text, title, focus or an expired summon refuses the operation. **Refine Buddy draft** intentionally edits only Buddy's own composer and is labelled accordingly.

Passive local prompt suggestions remain off by default and use one supported focused field's bounded text events after opt-in. No global typing log, passive screenshot capture, clipboard replacement, incidental prompt persistence, shell execution or cloud audio is introduced. Safe replacement requires UIA Edit/Value support; contenteditable/custom/terminal controls may be unavailable. Refusal must never silently redirect an external edit into Buddy Home.

The core follows the Windows Clicky reference's resident tray lifetime, direct voice interaction, cursor-adjacent state and teaching pointers. Optional action agents, refinement, region selection and local knowledge are kept distinct. Reference source was inspected at [app.py](https://github.com/AbhishekVulla/clicky-windows/blob/main/app.py), [overlay.py](https://github.com/AbhishekVulla/clicky-windows/blob/main/overlay.py), and [tray.py](https://github.com/AbhishekVulla/clicky-windows/blob/main/tray.py). Its source license is MIT; no reference code, artwork or PyQt implementation was imported. Buddy retains native WPF and its existing privacy/approval boundaries.

The source includes the accumulated offline voice, configurable shortcuts, capture protection, headphone policy, bounded teaching/approved action continuation, local job/knowledge storage, and owner-supplied branding/expression work. Optional Piper runtime and models are installed separately only by explicit setup; weights, runtime environments, user data and recovery archives are not in Git. Preserve their own licenses when redistributing an optional bundle. Existing local C/F3 selections remain supported. Account grants are hard-disabled; connector protocol fixtures are not connected accounts.

Validation distinguishes pure policy and mocked service tests, actual owned WPF/UIA fixtures, package/startup checks, and physical/third-party acceptance. The separate-process source fixture intentionally uses identical text in its source field and Buddy Home; it checks the actual MainWindow route, Accept/Undo, scoped text/focus invalidation, Home close and actual Exit. It never drives ChatGPT, Codex or other third-party software. CI runs source/version checks, service/policy tests, native rendering/OCR packaging checks and Android build/lint. Focus-sensitive and physical audio acceptance are local/manual checks.

Remaining user acceptance: the actual supported AI composer, Notepad/Amoeba lesson/capture behavior, competing shortcut apps, microphone recognition/voice quality, and active headphone disconnect/default-device changes. Offline voice quality depends on the selected model and hardware. Pointer grounding remains evidence-bound; unsupported controls do not receive guessed actions.
